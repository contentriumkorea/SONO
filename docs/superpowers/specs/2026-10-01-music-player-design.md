# 개인용 음악 플레이어 설계

작성일: 2026-10-01 · 상태: 사용자 검토용

## 목적과 완료 조건

사용자는 AIMP의 기능을 참고한 음악 플레이어를 macOS에서 사용하고, Windows에서 소스를 수정하여 GitHub에 새 버전을 배포하고 싶다. UI는 AIMP를 복제하지 않고 새롭게 디자인한다. 개인용이며 기능 우선순위는 제작자가 정하도록 위임받았다.

첫 버전의 완료 조건은 실제 로컬 음악을 가져와 재생하고, 재생목록과 설정을 다시 실행해도 유지하며, Windows 검증을 통과하고 macOS용 설치 파일을 생성하는 배포 설정을 갖추는 것이다. macOS 실기기 검증과 GitHub에서 실제 실행한 빌드 결과는 로컬 Windows 검증과 구분하여 보고한다. 설정 파일만 작성한 상태를 실제 배포 완료로 표현하지 않는다.

## 구현 방식 비교와 선택

| 방식 | 장점 | 고려 사항 |
| --- | --- | --- |
| Electron + React + TypeScript | Windows 개발과 macOS 패키징에 적합하고 디자인 자유도가 높다 | 앱 크기와 메모리 사용량이 상대적으로 크다 |
| Tauri | 설치 파일이 작고 시스템 기능 연결이 가능하다 | OS별 웹뷰의 음악 형식 지원 차이와 Rust 도구 설정이 추가된다 |
| macOS 전용 Swift | macOS와 자연스럽게 통합된다 | Windows 중심 개발·검증이라는 목표와 맞지 않는다 |

Electron을 선택한다. React는 화면, Electron은 파일 접근과 창 관리, TypeScript는 공유 데이터 구조에 사용한다. 패키징은 electron-builder, macOS 빌드는 GitHub Actions로 구성한다. 별도 서버와 로그인은 필요하지 않다.

## 첫 버전 기능

| 영역 | 구현 범위 |
| --- | --- |
| 가져오기 | 음악 파일 및 폴더 선택, 폴더 내부 검색, 추가 진행 표시, 중복 파일 제외 |
| 음악 정보 | 제목·가수·앨범·트랙 번호·길이·앨범아트 읽기, 정보가 없으면 파일명 사용 |
| 보관함 | 전체 곡·앨범·좋아요 보기, 제목·가수·앨범 검색, 정렬 |
| 재생 | 재생·일시정지·이전·다음·탐색·음량·음소거, 반복 해제/전체/한 곡, 셔플 |
| 재생 대기열 | 다음 재생에 추가, 대기열 보기 및 제거, 현재 곡 표시 |
| 재생목록 | 생성·이름 변경·삭제·곡 추가 및 제거·순서 변경, M3U 가져오기 및 내보내기 |
| EQ | 20밴드 이퀄라이저, 활성화/해제, 프리앰프, 프리셋과 사용자 설정 저장 |
| 편의 기능 | 미니 플레이어, 창 내부 단축키, 미디어 키 연동, 취침 타이머 |
| 상태 저장 | 보관함·목록·좋아요·음량·EQ·최근 곡 및 재생 위치 유지, 실행 시 자동 재생하지 않음 |
| 업데이트 | 현재 버전 표시, 설정한 GitHub 저장소의 새 릴리스 확인, 릴리스 페이지에서 설치 파일 다운로드 |

음악 형식은 MP3, WAV, FLAC, M4A/AAC, OGG를 우선 대상으로 한다. 컨테이너·코덱별 실제 재생 결과를 기록하고 실패한 파일은 이유를 표시한다. AIMP가 지원하는 모든 형식을 지원한다고 표기하지 않는다. DRM 음악은 첫 버전 대상이 아니다.

라디오·팟캐스트·클라우드·CD 추출·플러그인 및 AIMP 스킨 호환·원본 파일 태그 수정·형식 변환·CUE 트랙 분리는 이후 확장 대상으로 둔다. 첫 버전은 원본 음악을 이동하거나 덮어쓰지 않는다. 크로스페이드와 완전한 무간격 재생도 실제 검증 없이 지원 기능으로 표시하지 않는다.

## 화면 디자인

작업용 이름은 Luma Music으로 한다. 이름 변경은 구조 변경 없이 가능하도록 한다.

- 색상: 블랙 배경, 그레이 패널, 화이트 글자와 조작 버튼으로 구성한 무채색 테마.
- 왼쪽: 좁은 탐색 영역에 보관함, 앨범, 좋아요, 재생목록을 배치한다.
- 중앙: 앨범아트와 음악 정보를 보여주고 목록은 곡명·가수·앨범·길이가 읽기 쉽게 정렬한다.
- 하단: 현재 곡, 재생 버튼, 진행 막대, 음량을 항상 표시한다.
- 오른쪽: 사용자가 열었을 때만 재생 대기열을 보여준다.
- 미니 플레이어: 앨범아트, 곡명, 재생과 이전/다음 조작만 간결하게 표시한다.

큰 앨범아트와 절제된 간격을 중심으로 구성하고, 곡이 많아도 목록의 가독성을 우선한다. 기본 언어는 한국어다. 데스크톱 크기 변경과 키보드 포커스를 지원하고 버튼에 접근성 이름을 부여한다. 앨범아트가 없는 곡에는 앱 내부 기본 이미지를 사용한다. 실제 사용 화면에 예시 곡이 섞이지 않으며, 처음 실행하면 음악 가져오기 안내를 보여준다.

## 구성과 데이터 흐름

1. Electron 메인 프로세스가 파일 선택, 가져오기, 메타데이터 읽기, 영구 저장, 창 관리를 담당한다.
2. preload는 가져오기·보관함 조회·목록 저장 등 필요한 동작만 화면에 노출한다. 화면에는 임의 파일 접근 권한을 제공하지 않는다.
3. 등록된 곡 ID를 전용 미디어 프로토콜로 연결하고 실제 파일을 스트리밍한다. 탐색을 위해 범위 요청을 지원한다.
4. 화면의 오디오 엔진은 HTMLAudioElement와 Web Audio를 사용한다. EQ 설정은 재생 엔진에 연결하고 미니 창은 독립적인 재생 엔진을 만들지 않는다.
5. 보관함, 재생목록, 설정은 Electron 사용자 데이터 폴더의 버전이 있는 JSON 파일에 저장한다. 임시 파일 작성 후 교체하여 중간 저장 실패를 줄인다. 음악 자체는 복사하지 않는다.
6. 저장소 주소를 설정하면 GitHub 릴리스 정보를 읽어 최신 버전과 비교한다. 개인용 초기 배포에서는 설치 파일 교체 방식으로 업데이트한다.

주요 데이터는 Track(곡 ID, 경로, 정보, 앨범아트 참조), Playlist(목록 ID, 이름, 곡 ID 순서), Settings(음량, EQ, 창 상태, 저장소 주소), PlaybackState(현재 곡, 위치, 반복, 셔플, 대기열)로 분리한다. 오디오 재생 상태의 소유자는 하나이며 보관함 필터링이 재생 대기열을 의도치 않게 변경하지 않는다.

## 오류 처리

- 가져오기 실패는 파일별로 정리하고 읽을 수 있는 다른 파일은 계속 가져온다.
- 삭제되거나 이동한 파일은 찾을 수 없다고 표시하고 앱을 종료시키지 않는다.
- 손상되거나 지원하지 않는 코덱은 재생 오류로 표시한다. 반복 재생 시 실패한 곡 사이에서 무한 전환하지 않는다.
- 목록 삭제는 보관함과 원본 음악을 삭제하지 않는다.
- 저장 파일이 손상되면 복구 가능한 이전 파일을 보존하고 사용자에게 상태를 안내한다.
- 인터넷이 없거나 GitHub 조회가 실패해도 로컬 재생은 계속 사용할 수 있다.
- Electron은 contextIsolation과 sandbox를 사용하고 화면의 Node 통합을 끈다. IPC 호출과 곡 ID를 검증한다.

## 빌드와 배포

Windows에서 소스를 수정하고 로컬 앱을 실행한다. GitHub Actions는 macOS 환경에서 Apple Silicon(arm64)과 Intel(x64) 설치 파일을 각각 생성하도록 구성한다. Windows 패키지는 로컬 확인과 동일 소스 유지에 사용한다. 버전 태그를 배포 기준으로 사용하고 초기는 초안 릴리스에 설치 파일을 올려 확인 후 게시하는 방식으로 구성한다.

GitHub 저장소와 인증은 실제 배포 전에 연결한다. 비밀키와 토큰은 저장소에 넣지 않는다. 개인용 시험 설치와 Developer ID 서명·공증을 갖춘 배포를 구분한다. Developer ID 서명·공증은 인증서 및 Apple 개발자 계정이 확보되었을 때 구성한다. 계정이 없는 초기 버전은 시험 설치 방식과 macOS 보안 확인 절차를 문서에 명시한다. 서명되지 않은 초기 버전에 앱 내부 자동 설치를 약속하지 않는다.

## 검증 기준

- 알려진 테스트 오디오로 실제 재생, 일시정지, 탐색, 곡 종료 후 이동을 확인한다.
- 셔플·반복·대기열이 여러 곡 및 한 곡 조건에서 올바르게 동작하는지 확인한다.
- 가져오기 중복, 파일 누락, 잘못된 목록 파일, 저장 후 재실행을 확인한다.
- EQ 활성화와 비활성화, 프리셋 복구, 미니 창과 본 창의 상태 동기화를 확인한다.
- 타입 검사와 제품 빌드, 핵심 데이터 동작 테스트를 수행한다.
- UI의 빈 상태·오류 상태·긴 곡명·창 크기 변경을 실제 화면에서 확인한다.
- GitHub 빌드 실행과 macOS 설치·오디오 출력·미디어 키 검증은 가능한 환경에서 별도로 수행하고 미확인 항목을 남긴다.
