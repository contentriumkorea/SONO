## Global Constraints
- macOS and Windows share source; GitHub publishing is deferred by the user.
- Korean UI, black/gray/white palette, no sample songs mixed into the real library.
- Original music remains untouched; library data is in the app user-data directory.
- One playback engine; no autoplay on startup; 20-band EQ.

## Review Focus
- Missing files and corrupt audio must not cause endless next-track loops.
- Queue takes priority over ordinary playback order; manual next must leave repeat-one.
- Duplicate imports preserve favorites and don't produce duplicate rows.
- Stored data must survive restarts; corrupted JSON must remain recoverable.
- Range requests and unknown IDs must not expose arbitrary local files.

## File map
- src/shared/types.ts: IPC and persistence types.
- src/shared/library.ts: search, queue transitions, playlist sanitation.
- electron/store.ts: atomic persisted data with recovery.
- electron/library.ts: metadata reading, folder scan, M3U.
- electron/media.ts: bounded range request handling.
- electron/main.ts and preload.ts: desktop integration and isolated API.
- src/player.ts: one HTMLAudio/WebAudio graph.
- src/App.tsx, components, styles.css: library, playback controls and modal surfaces.
- scripts: build, start, integration verification.
