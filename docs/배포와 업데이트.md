# SONO 배포와 업데이트

저장소: https://github.com/contentriumkorea/SONO

설치 파일: https://github.com/contentriumkorea/SONO/releases/latest

## 사용자가 업데이트하는 방법

왼쪽 아래 **업데이트** → **업데이트 확인**을 누릅니다.

- Windows 설치 버전: **업데이트 다운로드** → **재시작하여 설치**. 자동으로 내려받거나 재생 중에 설치하지 않습니다.
- Mac 및 개발 실행: **설치 파일 받기**로 GitHub Releases를 열고 설치 파일을 받아 교체합니다.
- 업데이트 서버에 연결하지 못해도 로컬 음악 재생은 계속 사용할 수 있습니다.
- SONO의 기존 앱 ID와 `Luma Music` 데이터 경로를 유지해 기존 보관함·표시 이름·재생목록·설정을 이어 사용합니다. 음원 원본은 설치 파일에 포함하지 않습니다.

## Windows에서 새 버전 배포

1. 소스를 수정합니다.
2. `package.json`의 `version`을 올립니다. 정식 버전은 `0.1.1`처럼 숫자 세 자리로 지정합니다.
3. `pnpm check`로 검사합니다.
4. 소스를 저장소에 올립니다.
5. GitHub **Actions → SONO → Run workflow**를 실행합니다. 또는 버전과 같은 태그(`v0.1.1`)를 푸시합니다.

GitHub Actions가 Windows NSIS 설치 파일과 Mac 공용 DMG/ZIP을 빌드합니다. 두 빌드가 성공한 뒤 모든 설치 파일과 업데이트 메타데이터를 초안 릴리스에 업로드하고, 업로드 완료 후 공개합니다. 같은 버전은 덮어쓰지 않습니다.

```powershell
pnpm check
git add .
git commit -m "Release SONO 0.1.1"
git tag v0.1.1
git push origin main
git push origin v0.1.1
```

Windows에서도 GitHub의 Mac 빌드 작업을 실행할 수 있으므로 Mac 빌드용 컴퓨터를 직접 관리할 필요가 없습니다. Mac 설치·실제 오디오 출력은 Mac에서 별도로 확인해야 합니다.

## 로컬 설치 파일 생성

```powershell
pnpm release:win
# macOS에서 실행
pnpm release:mac
```

결과는 `release/`에 생성합니다. Windows 업데이트에는 설치 EXE, `.blockmap`, `latest.yml`이 필요합니다. 이 파일을 함께 배포해야 합니다. Mac은 공용 앱의 DMG/ZIP 및 `latest-mac.yml`을 빌드합니다.

## 첫 배포의 서명 범위

현재 별도 코드 서명 인증서를 사용하지 않는 시험 배포입니다. Windows 설치 시 게시자 확인 안내가 나올 수 있습니다. macOS에서는 시스템 설정의 개인정보 보호 및 보안에서 앱 실행을 허용해야 할 수 있습니다. 보안 기능을 전체 비활성화할 필요는 없습니다.

Mac에서 앱 내 자동 설치를 사용하려면 Apple Developer ID 서명·공증 구성이 필요합니다. 현재 Mac은 새 버전 확인과 설치 파일 페이지 연결을 제공합니다. 인증서·토큰은 소스나 앱에 포함하지 않습니다.
