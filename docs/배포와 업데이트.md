# MusicBoard 배포와 업데이트

저장소: https://github.com/contentriumkorea/SONO

설치 파일: https://github.com/contentriumkorea/SONO/releases/latest

## 사용자가 업데이트하는 방법

왼쪽 아래 **업데이트**를 열면 새 버전을 확인합니다. 새 버전이 있으면 **지금 업데이트**를 누릅니다.

- Windows·Mac 설치 버전: 버튼 한 번으로 다운로드 → 설정 저장 → 앱 교체 → 재실행합니다.
- 0.1.2 이하의 Mac에는 자동 교체 코드가 없으므로 0.1.3 앱으로 최초 한 번 직접 교체해야 합니다. 0.1.3부터 이후 버전은 앱 안에서 업데이트합니다.
- Mac은 DMG 안에서 실행하지 말고 응용프로그램 폴더에 옮겨 실행하세요. 앱 폴더에 쓰기 권한이 있어야 합니다. 새 앱이 정상 실행되지 않으면 이전 앱으로 복구합니다.
- 개발 실행에서는 **설치 파일 받기**로 설치 파일 페이지를 엽니다.
- 업데이트 서버에 연결하지 못해도 로컬 음악 재생은 계속 사용할 수 있습니다.
- MusicBoard의 기존 앱 ID와 `Luma Music` 데이터 경로를 유지해 기존 보관함·표시 이름·재생목록·설정을 이어 사용합니다. 음원 원본은 설치 파일에 포함하지 않습니다.

## Windows에서 새 버전 배포

1. 소스를 수정합니다.
2. `package.json`의 `version`을 올립니다. 정식 버전은 `0.1.1`처럼 숫자 세 자리로 지정합니다.
3. `pnpm check`로 검사합니다.
4. 버전을 올린 `package.json`과 소스를 `main`에 올리면 배포가 자동으로 시작됩니다.
5. GitHub **Actions → MusicBoard**에서 검증·설치 파일 생성·공개 결과를 확인합니다. 수동 배포는 **Run workflow** 또는 버전과 같은 태그(`v0.1.1`) 푸시로도 실행할 수 있습니다. 같은 버전을 여러 방식으로 중복 실행할 필요는 없습니다.

GitHub Actions가 Windows NSIS 설치 파일과 Mac 공용 DMG/ZIP을 빌드합니다. 두 플랫폼의 단위 테스트·통합 검증과 Mac 패키지 자동 교체 검증까지 성공한 뒤 모든 설치 파일과 업데이트 메타데이터를 초안 릴리스에 업로드하고, 업로드 완료 후 공개합니다. 같은 버전은 덮어쓰지 않습니다.

```powershell
pnpm check
git add .
git commit -m "Release MusicBoard 0.1.1"
git push origin main
```

Windows에서도 GitHub의 Mac 빌드 작업을 실행할 수 있으므로 Mac 빌드용 컴퓨터를 직접 관리할 필요가 없습니다. Mac 설치·실제 오디오 출력은 Mac에서 별도로 확인해야 합니다.

## 로컬 설치 파일 생성

```powershell
pnpm release:win
# macOS에서 실행
pnpm release:mac
```

결과는 `release/`에 생성합니다. Windows 업데이트에는 설치 EXE, `.blockmap`, `latest.yml`이 필요합니다. 이 파일을 함께 배포해야 합니다. Mac은 공용 앱의 DMG/ZIP 및 `latest-mac.yml`을 빌드합니다.

## 첫 배포의 서명 범위

현재 별도 코드 서명 인증서를 사용하지 않는 시험 배포입니다. Windows 설치 시 게시자 확인 안내가 나올 수 있습니다. macOS에서는 시스템 설정의 개인정보 보호 및 보안에서 앱 실행을 허용해야 할 수 있습니다. 보안 기능을 전체 비활성화할 필요는 없습니다.

Mac은 ad-hoc 서명을 사용하며 Developer ID 서명·공증은 아직 구성하지 않았습니다. MusicBoard의 Mac 업데이트는 전용 교체 도우미를 사용합니다. GitHub의 기존 SONO 저장소에서 받은 ZIP의 크기·SHA-256, 앱 ID·버전·코드 서명을 확인한 뒤 교체하며 실패 시 이전 앱을 복구합니다. 시스템 보안 설정이나 음악 파일은 변경하지 않습니다. 인증서·토큰은 소스나 앱에 포함하지 않습니다.

참고: https://www.electron.build/v26/docs/auto-update/

기존 SONO 설치 앱과의 호환을 위해 저장소 URL, 앱 ID, Luma Music 데이터 경로와 내부 SONO 실행 파일명을 유지합니다. 새 설치 파일은 MusicBoard 이름을 사용하며, SONO 이름의 호환 파일도 함께 제공합니다. 기존 Mac 설치 위치의 SONO.app 파일명은 유지되지만 앱 화면·메뉴·제품명은 MusicBoard로 바뀝니다.
